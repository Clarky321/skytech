# ADR 0001 — Базовая архитектура SkyTech.ru

**Status:** Accepted (2026-11-08)

## Context

SkyTech.ru — технический портал (статьи, база знаний, документация, IT-инструменты) для
системных администраторов и инженеров. Разрабатывается одним разработчиком с Claude Code.
Нужны: хорошее SEO, быстрый публичный сайт, удобная редакция, безопасность админки,
хранение данных в РФ (152-ФЗ) и возможность роста без переписывания.

## Decision

1. **Modular monolith.** Одно приложение `apps/api` (NestJS) с тремя entry points:
   HTTP API (`main.ts`), worker (`main.worker.ts`), CLI (`cli.ts`). Модуль работает только со
   своими таблицами; к чужим данным — через сервис другого модуля. Микросервисов нет.
2. **Next.js app (`apps/web`)** — публичный сайт и админка (`/admin`) в одном приложении.
3. **Один origin.** nginx: `/api/*` → NestJS, остальное → Next.js. Public API — `/api/v1`,
   admin API — `/api/admin`.
4. **PostgreSQL 17 — единственный источник истины.** Redis (очереди BullMQ, rate limits, кэш) —
   только восстановимые данные.
5. **Transactional outbox** для всех побочных эффектов (ревалидация, IndexNow, индексация,
   уведомления). Никаких прямых внешних вызовов после commit в HTTP-обработчике.
6. **Content model:** одна таблица `content` с `type` (`article`, `page`; позже `kb`, `doc_page`).
   Ревизии неизменяемы; публичный сайт читает только опубликованный снимок.
7. ~~**Markdown — source of truth.**~~ **Заменено ADR 0002:** тело материала — строго валидируемый
   JSON-документ; HTML строит только `packages/content-render` на сервере; sanitize обязателен.
8. **Media** только в S3-совместимом хранилище; в документе — ссылка `mediaId` (ADR 0002); SVG и
   не-изображения запрещены в MVP.
9. **Auth:** серверные сессии (httpOnly cookie, в БД хэш токена), Argon2id, deny-by-default,
   `@Public()` для открытых маршрутов, CSRF-проверка Origin. JWT для браузера не используется.
10. **Contracts:** Zod-схемы в `packages/contracts` — единственное описание API.
11. **Migrations:** Drizzle, только `generate` + `migrate`, `push` запрещён, применённые
    миграции не редактируются.
12. **Search:** PostgreSQL FTS за `SearchService`.
13. **Tools:** чистые функции в `packages/tools-core`, в MVP работают только в браузере.

### Toolchain (зафиксировано в Phase 0.1)

- Node.js 24 LTS, pnpm (через corepack, версия в `packageManager`), Turborepo.
- **TypeScript 6.0.x**, а не 7.x: typescript-eslint поддерживает `typescript <6.1`,
  Nest CLI тоже собран на TS 6.0. Переход на TS 7 — когда экосистема его поддержит.
- **NestJS 12 — ESM-only.** `apps/api` — ESM-пакет (`"type": "module"`), импорты с `.js`.
- Внутренние пакеты (`contracts`, `content-render`, `tools-core`) компилируются `tsc` в `dist`
  (ESM + `.d.ts`); Turborepo собирает их до зависящих задач (`dependsOn: ["^build"]`).
- Тесты — Vitest во всех пакетах; для NestJS — через `unplugin-swc` (метаданные декораторов).
- **ESLint 9.39** (flat config, type-aware), а не 10: плагины внутри `eslint-config-next`
  (react, jsx-a11y, import) объявляют peer `eslint <=9`. npm помечает 9.x как deprecated —
  обновиться до 10, когда `eslint-config-next` его поддержит. Prettier для форматирования.
- pnpm блокирует install-скрипты зависимостей; разрешённые перечислены в `allowBuilds`
  (`pnpm-workspace.yaml`). Каждое новое разрешение — осознанное решение.

## Alternatives

- Отдельное admin-приложение — отклонено: лишний деплой и библиотеки для 1–5 сотрудников.
- Payload CMS / готовая CMS — отклонено: привязка к модели CMS, меньше контроля над процессом
  публикации и безопасностью.
- Микросервисы — отклонено: преждевременная сложность для одного разработчика.
- JWT-аутентификация — отклонено: сложнее отзыв, риск кражи токена при XSS.
- TS-исходники внутренних пакетов без сборки — отклонено: NestJS запускается в Node ESM
  без бандлера, поэтому пакеты должны быть скомпилированы.

## Consequences

- Один репозиторий, один язык, общие контракты между фронтендом и бэкендом.
- Любой модуль можно позже вынести в сервис — границы модулей проводятся уже сейчас.
- Пакеты нужно собирать перед typecheck/test/dev зависимых приложений (делает Turborepo).
- Изменение любого пункта этого ADR требует обсуждения и нового ADR.
