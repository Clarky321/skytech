# ADR 0002 — Структурированный документ и блочный редактор (TipTap)

**Status:** Accepted (2026-11-08). Заменяет пункт 7 ADR 0001 («Markdown — source of truth»).

## Context

Редакции нужен визуальный блочный редактор уровня Confluence/Notion: заголовки, таблицы,
блоки кода с выбором языка, изображения с подписью и alt, цветные callout-блоки
(info/warning/danger/success), чек-листы, перетаскивание блоков, slash-команды.

Исходный план (ADR 0001) делал Markdown источником истины. Проверка показала:

- Таблицы со сложным содержимым, callout-блоки, изображения с подписью и параметрами не имеют
  стандартного представления в Markdown — нужны нестандартные директивы и HTML-вставки.
- Двусторонняя конвертация «редактор ↔ Markdown» теряет данные (вложенные списки в таблицах,
  выравнивание, атрибуты), а каждая потеря — тихая порча контента.
- Хранить два редактируемых представления одного документа запрещено (одна правда).

## Decision

### 1. Редактор — TipTap 3 (MIT)

Рассмотрены:

| Критерий            | TipTap 3                              | BlockNote                                     |
| ------------------- | ------------------------------------- | --------------------------------------------- |
| Лицензия            | MIT (включая DragHandle, Table, List) | MPL-2.0 ядро, часть пакетов GPL-3.0/коммерция |
| Модель документа    | ProseMirror JSON, своя схема          | собственная блочная модель поверх ProseMirror |
| Свой UI             | полностью свой (Tailwind/shadcn)      | готовый UI (Mantine/shadcn), сложнее менять   |
| Таблицы, код, медиа | официальные расширения                | есть, но кастомизация через их API            |
| Кастомные блоки     | Node + React NodeView                 | custom blocks, ограниченнее                   |
| Серверный рендеринг | JSON обходится нашим рендерером       | нужен их рендерер или конвертер               |

Выбран TipTap: свободная лицензия, полный контроль над схемой и UI, зрелая экосистема ProseMirror.
BlockNote не устанавливается.

### 2. Источник истины — JSON-документ SkyTech (подмножество ProseMirror JSON)

- Тело материала хранится в `content_revisions.body` (`jsonb`) — **единственное редактируемое
  представление**. Markdown больше не используется для хранения.
- Схема документа описана Zod-схемой в `packages/contracts` (`documentSchema`): только
  разрешённые узлы и marks, ограничения длины, проверка URL ссылок (`http`, `https`, `mailto`,
  относительные `/…` и якоря `#…`). Неизвестный узел, атрибут или опасный URL → `422`.
  Сервер не доверяет данным редактора.
- Изображения ссылаются на медиа по `mediaId` (аналог `media:ID`), а не по URL.
- HTML строит **только** `packages/content-render` на сервере: JSON → HAST (`hastscript`) →
  `hast-util-sanitize` (строгая схема) → `hast-util-to-html`. HTML, TOC, время чтения и
  plain text для поиска вычисляются при сохранении ревизии и хранятся в ней (ревизия неизменяема).
- Заголовки тела H1–H4 рендерятся на странице как `h2`–`h5`: `h1` страницы — заголовок статьи.
- Подсветка кода — `lowlight` (highlight.js) и в редакторе, и в серверном рендерере: один
  движок, одинаковый результат, темы через CSS-классы (светлая/тёмная без дублирования HTML).
  Shiki из исходного плана не используется.

### 3. Последствия для смежных решений

- **Поиск (Phase 7):** индексируется `plain_text`, извлекаемый рендерером из JSON.
- **Экспорт и миграции:** JSON-схема версионируется (`content_revisions.body_schema_version`, константа `DOCUMENT_SCHEMA_VERSION`). Экспорт в
  Markdown/HTML — функция рендерера (односторонняя), не второе хранилище.
- **Ревизии:** каждая ревизия хранит JSON + производные (HTML, TOC, plain text). Опубликованный
  снимок — ссылка `content.published_revision_id`.

## Сопутствующие упрощения первого вертикального среза

- **Загрузка медиа через API (multipart), а не presigned URL.** Сервер проверяет сигнатуру файла
  до сохранения, перекодирует изображение через `sharp` (EXIF удаляется) и кладёт варианты в S3.
  Для изображений ≤ 10 MB это быстрее и безопаснее: в бакет никогда не попадает непроверенный
  файл. Presigned upload можно вернуть, если понадобятся большие файлы.
- **Worker без BullMQ.** `main.worker.ts` — цикл опроса PostgreSQL (`FOR UPDATE SKIP LOCKED`):
  публикация запланированных материалов. BullMQ подключается, когда появятся задачи, которым
  нужна очередь (Phase 7–8). Outbox-события пишутся в транзакциях уже сейчас.
- **Публичные страницы рендерятся динамически** (без кэша Next.js), поэтому ревалидация после
  публикации не нужна. Кэширование с ревалидацией из worker — Phase 6.3/8.
- **Собственная ручка блока вместо `@tiptap/extension-drag-handle`.** Официальное расширение требует
  peer-зависимостей для совместного редактирования (Yjs, `@tiptap/y-tiptap`, collaboration). Ручка
  блока (меню + перетаскивание через `view.dragging` ProseMirror) реализована в `apps/web/src/editor`.
- **Публичные страницы и админка — Tailwind 4 + собственные компоненты в стиле shadcn/ui на `radix-ui`.**
- **MinIO для разработки — `bitnamilegacy/minio`.** Официальные образы MinIO больше не
  публикуются; legacy-образ Bitnami — замороженная сборка MinIO, только для локальной среды.
  Замена при необходимости — SeaweedFS. В production — S3 провайдера.

## Alternatives

1. **Markdown как источник + конвертация в редактор** — отклонено: потери при round-trip,
   нестандартные расширения для callout/таблиц/подписей.
2. **Гибрид (JSON для редактора + Markdown копия)** — отклонено: два представления неизбежно
   расходятся; нарушает правило одного источника истины.
3. **HTML как источник** — отклонено: XSS-поверхность, сложная валидация.

## Consequences

- (+) Редактор без потерь данных, богатые блоки, строгая серверная валидация структуры.
- (+) Рендеринг из типизированного дерева проще защитить от XSS, чем Markdown с HTML.
- (−) Контент нельзя удобно править как текст в git; экспорт — через рендерер.
- (−) Изменение схемы документа требует миграции данных (`body_schema_version`).
